# 本地部署自检

`npm run doctor` 在启动前检查本部署的 Node、目录权限、SQLite、主密钥与必要配置。**只报告，不联网，不输出秘密，不创建或修复数据。** 不需要登录应用，也不会查询站点。

## 使用

先安装锁定依赖，再按需要初始化管理员：

```powershell
npm ci
npm run setup
npm run doctor -- --development
npm run dev
```

已有部署不要重复 setup。检查生产配置用：

```powershell
npm run doctor
```

供脚本读取的纯 JSON（`--silent` 去掉 npm 自身的命令标题）：

```powershell
npm run --silent doctor -- --json
npm run --silent doctor -- --json --development
```

也可直接执行 `node scripts/doctor.mjs --json`。**从应用目录运行，并使用与实际服务相同的用户及环境变量**；权限和相对数据路径按当前工作目录解析。

退出码：

| 状态 | 退出码 | 含义 |
| --- | --- | --- |
| PASS | 0 | 本次支持的本地检查全部通过，不代表外站查询或实际部署成功 |
| WARN | 1 | 有未初始化、未验证或需人工确认项，没有已确认失败 |
| FAIL | 2 | 至少一个配置、权限、数据库或密钥检查失败，或参数无效 |

首次启动前数据库/密钥/数据目录尚未创建，是正常的 WARN；不会为获得 PASS 自动初始化。WARN 返回非零，请阅读建议，不要直接把它当作程序崩溃，也不要用 `&&` 链忽略这个区别。

## 检查范围

- **Node**：按 package.json 的最低要求 22.20.0 检查；版本不支持时不加载配置文件、数据库或主密钥。
- **数据目录**：确认配置能解析为目录，检查读、写、访问权限。目录不存在则检查最近的已有父目录，只报告，不创建目录或写入探针。`access` 是权限预检，**不是实际写入、Windows ACL、只读挂载或磁盘剩余空间的完整证明**。
- **SQLite 驱动**：在内存中实际打开并关闭连接，发现原生模块/Node 兼容问题；不执行 npm 安装或下载。
- **数据库**：读取最多 64 MiB 的普通文件到内存；以只读连接做 `quick_check(1)` 和必要表/列检查。不会在原数据库上打开 SQLite 连接，不产生/合并 WAL、SHM 或执行迁移。不会读取账号名称或历史 payload。
- **管理员**：数据库已保存的 adminHash 优先，只验证格式，不输出哈希、不尝试登录。环境变量密码/哈希仅用于首次初始化，不会覆盖已有密码。
- **主密钥**：有效环境密钥优先于 vault.key。环境值必须恰好 64 个十六进制字符，文件必须为原始 32 字节。数据库检查可用时逐条进行已保存加密凭据的本地认证，不输出解密结果。
- **公开地址**：未设置时提示仅本机使用；公网 origin 要求 HTTPS，本机回环可用 HTTP。不接受带登录信息、路径、参数的地址；不验证 DNS、TLS 或反向代理。
- **查询配置**：DNS 模式仅 system/cloudflare；代理只检查 HTTP/HTTPS CONNECT 配置格式；私有主机列表只允许小写精确主机名，不接受通配符/协议/端口。不连接代理、不解析域名。

所有普通输出及 JSON 结果只包含检查项、状态、固定错误码和建议。不会输出原始异常、路径、主机名、IP、配置值、密码、哈希、主密钥、账号、凭据、响应内容或余额。`--help` 只展示用法，未知参数不会回显。

## 配置优先级

默认检查 **production**。`--development` 切换到开发模式；命令不依赖父进程的 NODE_ENV 来猜测部署模式。

从高到低：

1. 已存在的 shell/容器环境变量。
2. `.env.production.local`（开发模式为 `.env.development.local`）。
3. `.env.local`。
4. `.env.production`（开发模式为 `.env.development`）。
5. `.env`。

通过应用已有的 Next 环境加载器处理引号及 `$VARIABLE` 展开，不执行配置内容为代码。环境文件不可读、不是普通文件、超过 1 MiB 或加载器报错时返回 FAIL，原始日志被抑制。检查 `.env` 本身不会显示它的内容；开发验收只使用合成夹具。

## 警告与恢复建议

### 数据库尚未初始化

配置有效后由正常应用启动创建空数据库；doctor 不创建它。首次尚无主密钥时会给出 WARN。已有数据库却缺少原密钥为 **FAIL**，不能靠生成一把新密钥解决。

### 存在恢复日志 / 数据库正在变化

存在非空 WAL 或回滚日志（atlas.sqlite-journal），或读取期间出现日志/文件变化时，返回 WARN，数据库健康、已有管理员及凭据匹配均保持未验证。**安全停止服务后重试**。不要删除 WAL/SHM/回滚日志，也不要在服务运行时只复制 atlas.sqlite。仅凭长度不能证明回滚日志是热日志，因此自检保守跳过，不自行恢复或误把未提交的主文件页当作就绪数据。

**主文件缺失但仍有 WAL、SHM 或回滚日志时为 FAIL / DATABASE_RECOVERY_INCOMPLETE**，不是普通首次部署。停止初始化、保留残留文件与原密钥并恢复完整备份；doctor 不建议启动空库，不生成主文件，也不丢弃剩余恢复材料。

### 数据库超过 64 MiB

返回 WARN，避免把无限增长的历史记录加载到内存。停止服务，先保留完整备份，再用可信 SQLite 工具检查备份的健康状态。此时 doctor 只检查主密钥格式，**不宣称与现有凭据匹配**。

### 旧版排序元数据

基础表结构和健康检查通过，但缺少已知的历史排序列时返回 WARN。保留完整备份后由应用执行已有启动迁移；doctor 不迁移、不修改历史记录。

### 密钥认证失败

停止服务并恢复与数据库配套的原始 vault.key 或原 RELAYDOCK_VAULT_KEY。正确长度不能证明密钥匹配；某些账号使用不同密钥或密文损坏也会失败。认证通过只证明本地密文可读取，**不证明上游凭据仍有效或外站查询成功**。没有加密凭据时无法验证历史密钥的身份。

### 已有管理员密码与环境变量不一致

已有数据库使用保存的密码，不会因修改环境变量而重置。若数据库哈希格式无效或忘记密码，保留完整备份、停止服务后使用 `npm run setup -- --reset-password`；doctor 不重置密码或注销会话。

## Docker 入口（镜像实测仍待完成）

Dockerfile 已配置保留 doctor 脚本及其环境加载器。运行中的容器可以执行：

```powershell
docker compose exec atlas node scripts/doctor.mjs --json
```

运行中的 WAL 通常需要停止服务后再检查。若要检查同一个数据卷但不启动应用：

```powershell
docker compose stop atlas
docker compose run --rm --no-deps atlas node scripts/doctor.mjs --json
docker compose start atlas
```

重新启动是用户的显式操作，不是 doctor 的自动行为。此入口目前只有源码/白名单与单测验证，**尚未实际在 Docker 镜像中执行**；不替代 [Docker 持久化与迁移验收](DOCKER-VERIFICATION.md)。

## 备份边界与验收

JSON 导出是**不含凭据的数据备份**。完整迁移仍需要数据库（包含可能存在的 WAL/SHM/回滚日志）、对应主密钥及必要部署配置；doctor 不是备份或恢复工具。

测试通过临时合成 cwd/SQLite/key 与阻断网络、子进程的 preload 验证。实际单测数量及完成状态见 [当前状态](STATUS.md)；不能把脚本检查通过当作真实站点、反向代理、Docker 或远端 CI 已验收。
