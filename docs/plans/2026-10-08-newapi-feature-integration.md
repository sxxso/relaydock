## 结论

最适合先加入 Atlas 的是「模型表现」「手动／批量签到」「签到记录」。它们可以沿用多账号、分组、加密凭据、直连／代理、查询诊断和历史记录的基础设施。模型表现继续按点击读取，签到通过单独的显式操作提交。

参考项目是浏览器扩展，Atlas 是独立部署的网页应用。因此，接口数据解析可以参考；Cookie 会话、标签页注入、Turnstile 和浏览器定时器需要另外设计，不能把 background.js 直接搬到后端。

## 第一阶段：模型表现

### 数据路径

参考 `background.js:1420–1828`：

1. `/api/status` 读取站点版本、配额换算提示和模块开关。
2. `/api/pricing` 读取站点公布的模型目录与分组，作为展示目录。
3. `/api/perf-metrics/summary?hours=24|72|168` 读取模型概览。
4. 用户展开模型时，再读 `/api/perf-metrics?model=...&hours=...`，显示分组明细和趋势。
5. 确认性能接口不支持时，读取 `/api/log/self`，汇总当前账号的消费／失败日志。参考扩展为每页 100 条、最多 6 页；Atlas 也应限制页数、响应大小及整次操作时间，并明确显示是否截断。

权限错误、网络失败和接口不支持分别显示。401／403 不应被解释成接口不存在；允许用户明确选择「我的调用记录」作为另一种数据来源。日志不可读时保留模型目录，显示「无指标」。

### 展示与口径

- 账号详情加入「模型」页签：24／72／168 小时、搜索、仅看有流量、排序、展开趋势。
- 显示来源、统计窗口、读取时间；有样本数量时展示样本数量，缺失时显示未知。
- 分开标注「站点公开流量统计」和「我的调用记录」。上游指标覆盖的分组范围也要保留。
- 模型列在目录中、指标正常、当前账号有权限和此刻实际调用成功是不同信息。目录或历史统计不能证明即时可用。
- 无流量、权限不足、接口不支持、读取失败不能一律显示为模型异常。
- 日志中的 `use_time` 是请求时长，用输出 Token 除以它只能称为「日志估算输出速度」。上游性能指标可能采用生成阶段时长，二者不应混排成同口径 TPS 排行榜。
- 个人日志成功率只描述返回日志中的记录；不保证包含全部失败、重试或完整窗口。
- 第一阶段不发送模型推理请求。列表数据和单模型趋势按用户点击读取，旧缓存显示读取时间，不自动轮询。

### 上游变化需要兼容

参考扩展读取 `recent_success_rates`；当日上游 `ModelSummary` 使用 `recent_success_series`（时间戳与成功率）。接入时用明确的兼容解析与夹具测试覆盖两种结构，缺字段时不能伪造趋势。

上游概要 `request_count` 未作为 JSON 字段公开，不能在站点统计模式凭空显示样本量。参考扩展按照成功率阈值分为优／良／波动／异常；Atlas 应同时展示原始指标和数据限制，避免一条成功日志就给出可靠性结论。

## 第二阶段：签到与记录

### 用户流程

账号详情加入「签到」页签，显示最近读取的今日状态、本月日历、奖励和时间；首次为未知，用户点击「查询签到状态」。支持时提供「立即签到」，其操作与余额刷新分开。

批量签到先显示范围和数量，跳过归档、不支持、已签到及正在操作的账号。结果区分成功、已签到、需要网页处理、失败、结果待确认，能够定位到账号。沿用现有批量查询的并发上限 3，并限制同一站点的并发；确认同站同用户的重复卡片时避免重复提交。

### 请求与状态

- 状态与本月记录：`GET /api/user/checkin?month=YYYY-MM`。
- 执行：`POST /api/user/checkin`；奖励来自响应 `quota_awarded`，日期来自 `checkin_date`。
- 读取状态优先采用 `stats.checked_in_today`。签到日期由站点确定，不仅按本机零点判断是否该签。
- HTTP 200 仍可能是业务失败；必须解析 `success` 和响应结构。
- 先读状态再提交；同账号加执行锁。锁和去重降低重复操作，不能承诺跨系统严格只执行一次。
- 已提交但读取响应超时时标记「结果待确认」，下一步只读查询状态；不能自动重复 POST。
- 签到成功后可在同一次明确操作中刷新余额，界面事先说明会追加查询。余额刷新失败时保留签到成功和旧余额，分别报告结果。
- 签到奖励单独记录。余额快照仍来自成功余额查询，不直接把奖励加到旧余额，避免与并行消费或旧数据冲突。
- 原始配额与换算奖励分开。沿用 Atlas 已确认的换算系数和单位；未确认时展示配额，不固定按 500000 换算或跨站求和。

### 支持范围

首轮支持管理令牌／个人访问令牌可以调用的标准 New API 签到站点；具体权限依站点版本与令牌范围而定。余额可读不代表签到可写。模型 API Key 与管理凭据分开，CC Switch 中的模型 Key 不能直接当作签到令牌。

需要登录会话或 Turnstile 时显示「打开站点完成」，完成后由用户刷新状态。Atlas 后端没有用户在 Edge／Chrome 的登录上下文；在 Atlas 域名上放验证码也不能代替目标站点上下文。

Agent Router 的读取自触发、退出／OAuth 重新登录／额度激活是参考项目的特殊流程（`background.js:948–1003`），应作为独立站点适配能力，不套进通用 GET 查询或余额刷新。

## 第三阶段：用量、比较和导入

### 月度用量

优先检查站点提供的个人聚合统计接口，再按需使用有界分页日志。标明时间范围、完整／采样、Token 字段口径与单位。上游账户累计 `used_quota` 和 `request_count` 不能直接叫本月消耗／本月调用。

只保存需要的数值聚合，不保存原始日志中的提示词、内容、IP、令牌名等字段。任何一项不可读时显示未知，其他已读数据可以独立展示。

### 跨站比较与 CC Switch

从收藏模型开始，让同一个模型按站点并排查看来源、分组、成功率、延迟、速度、余额与时间。模型别名由用户确认映射；同名也可能采用不同上游或计费规则。

Atlas 提供选择依据；CC Switch 继续承担 Codex／Claude 的配置和路由。后续可以单独设计模型目录导出或只读导入，但本轮不需要接管 CC Switch 的切换、故障转移或写它的数据库。

### 配置导入

参考 `popup.js:833–861` 的 JSON 导出／导入结构，映射名称、baseUrl、userId 和访问令牌；同域多账号必须保留，不能只按域名去重。

导入先在内存校验与预览，不自动查询。管理令牌进入现有加密凭据库；参考导出可能包含访问令牌和保活模型 Key，不能把原始导出复制进文档、Git、浏览器日志或 Atlas 数据备份。Cookie 模式仅迁移元数据并标明需要浏览器配合，不能宣称登录状态已经迁移。

## 后续能力的额外设计

### 浏览器协作

可沿用参考扩展作为浏览器端工具，或以后做小型配套扩展：目标站点会话与验证码留在浏览器，Atlas 展示操作结果。扩展与 Atlas 的配对认证、允许的来源、目标站点和账号身份校验应单独设计。

### 定时签到

现有 Atlas 按点击查询，因此自动签到需要新增每账号关闭默认的调度选项。独立部署应采用持久化任务和执行锁，明确时区、补检、停机恢复及人工介入；不能只用网页 `setInterval` 或 Next.js 请求进程中的易失计时器。需要网页交互的任务转为待处理，不宣称无人值守成功。

### 真实模型测试／保活

1.7.0 新增保活：批量／定时签到前真实发出最小模型请求；不支持默认模型时可读取目录并随机换模型重试。该能力可能消耗额度，与只读模型面板必须分开。

若以后实现，使用独立模型凭据和协议选择，明确具体模型、请求次数及可能费用；测试成功只代表该次调用。管理令牌不自动回退作模型 Key，批量签到不默认捆绑付费调用，避免随机模型重试引入不可预期费用。

## Atlas 的代码接入点

| 现有位置 | 已有基础 | 建议扩展 |
| --- | --- | --- |
| `src/lib/adapters/types.ts` 与 `adapters/newapi/` | 静态平台元数据、余额请求／解析 | 分别建立签到、目录、指标、日志能力；不把所有功能强塞进 BalanceAdapter |
| `src/lib/outbound.ts` | GET、DNS／IP 校验、直连／代理、压缩与大小限制、总超时 | 按明确操作允许 GET／POST、公共接口可省略认证头、受控查询参数与小请求体；保留已有网络约束 |
| `src/lib/validation.ts` | 账号和查询设置的声明式校验 | 增加可选能力设置；管理与模型凭据按用途区分；旧账号默认保持现状 |
| `src/lib/api.ts` | 登录、Origin／CSRF、查询锁与诊断 | 独立的模型读取、签到状态、签到提交路径；点击触发的外站读取沿用受保护 POST |
| `src/lib/store.ts` | 加密凭据、账号、余额快照、事务备份 | 签到记录、模型聚合缓存及读取时间；不混入余额快照；旧库／备份兼容 |
| `src/components/workspace.tsx` | 详情、筛选、批量操作与线路捕获 | 详情页签和明确批量范围；操作开始时固定所选线路 |

当前出站代码明确写死 `method: "GET"`（`outbound.ts:429`），所以「立即签到」需要受控传输扩展，并非补一个按钮就能完成。公共目录／指标请求也应按是否需要认证决定发送头，不向不相关接口发送管理凭据。

## 每阶段的验收重点

1. 模型：旧／新趋势字段、404／401／403、无流量、目录可读但指标不可读、600 条截断、分页中途失败、不同数据源、旧缓存和手机表格；断言没有推理请求或签到请求。
2. 签到：今日已签、关闭功能、成功后余额刷新失败、HTTP 200 业务失败、POST 响应超时、重复点击、同站多账号、站点日期与单位；真实账号操作只能来自用户点击。
3. 存储与界面：旧数据／备份兼容、凭据不公开、CSRF、原余额查询和直连／代理继续工作，切换页签和打开地图没有额外外站请求。

推荐实施顺序：模型表现 → 标准接口的手动／批量签到与历史 → 用量／跨站比较／导入 → 浏览器协作与可选定时。
