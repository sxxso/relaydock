> For agent: 使用 Superpowers 执行计划、TDD、只读评审与完成前验证。用户已批准路线图并要求完成第五阶段；不提交/推送，不开始下一阶段。

**目标：** 七个查询平台独立维护请求/解析/能力/响应夹具/验证记录，保留旧行为与声明式配置。
**架构：** `src/lib/adapters/<provider>/{index.ts,metadata.ts,fixtures.json}`；穷尽静态注册表分发。浏览器目录仅引用 metadata，不带解析、凭据或网络。公共层统一 URL 规范化、金额检查与失败分类，`query-balance.ts` 独占出站与诊断编排，`new-api.ts` 保留兼容导出。
**技术：** 现有 TypeScript / Decimal / Zod / Vitest / 隔离 Playwright，无新依赖、数据迁移或插件运行时。

## 步骤与验收

1. 阅读当前七平台合同；新增 `tests/adapter-contract.test.ts`：穷尽注册、目录/metadata 同源、每平台响应与错误夹具、请求地址/认证/用户 ID、无网络副作用；先运行 RED。
2. 创建合同与纯公共工具、七平台目录和静态注册表；保留账户/令牌、零/未知、币种/原始配额、精确小数及旧 API 导出；运行 GREEN 和旧平台/core 回归。
3. 扩充本地 HTTP + 临时 SQLite 平台 API 回归，覆盖七个平台测试与同步、失败保留、认证头/用户 ID 和无额外请求。依旧使用受保护 test/sync 与草稿测试路径。
4. 新增 `docs/ADAPTERS.md` 与 `CONTRIBUTING.md`，列出字段合同、兼容格式、夹具/文档/实站日期、贡献步骤与不执行脚本约束；README 链接。真实站点全部标为未实测，SiliconFlow 明确旧接口兼容。
5. 独立只读评审，重要问题必须反例 RED→GREEN；新鲜单测、typecheck、build，以及平台/向导/诊断/新鲜度/管理/交互/原界面回归使用同一构建。
6. 更新 `docs/STATUS.md` 和路线图，保存 `output/stage5-acceptance.json`，清理自有临时服务。只读本短计划和相关目录即可续接。

## 不变边界

- 点击才查询，不轮询、不自动重试，不自动试探其他端点，不做域名猜平台。
- 不读写真实 `.env.local`、SQLite、凭据、管理员密码或主密钥；所有查询测试使用隔离夹具。
- DoH 不启用，不加入代理。安全 DNS 固定 IP、禁止重定向/元数据及默认内网拒绝沿用出站层。
- 无 `eval`/`Function`、用户脚本、运行时插件下载或动态模块路径。兼容按响应合同描述，不伪称某版本/实站均已验证。
