# New API 签到与月历 Implementation Plan

> **For agent:** REQUIRED SUB-SKILL: Use Superpowers Section 5 to implement this plan.

**Goal:** 完成用户已批准的第二阶段：标准 New API 的手动／批量签到、站点月历与本地操作记录。
**Architecture:** 独立的 checkin 类型、解析与服务复用受控出站传输、加密管理凭据和连接版本。缓存 GET 不访问外站；受 CSRF 保护的 POST 分别读取状态、执行签到、执行明确范围的批量签到。独立 SQLite 表保存白名单数据和结果待确认屏障，界面沿用 Atlas 详情模态框与现有主题。
**Tech Stack:** Next 16 / React 19 / TypeScript / Zod / SQLite / Vitest / Playwright。

## Task 1：后端、受控传输和存储

Create `src/lib/checkin.ts`, `src/lib/query-checkin.ts`, `src/lib/checkin-service.ts`, `tests/checkin.test.ts`, `tests/checkin-api.test.ts`; modify `src/lib/outbound.ts`, `src/lib/store.ts`, `src/lib/api.ts`.

- 先写解析与 API 失败测试，运行 `npm.cmd test -- --run tests/checkin.test.ts tests/checkin-api.test.ts` 看到 RED，再实现并运行 GREEN。
- GET `/api/accounts/:id/checkin?month=YYYY-MM` 仅缓存。POST `/api/accounts/:id/checkin/status` 输入 `{month?,routeMode?}` 查询站点；POST `/api/accounts/:id/checkin` 输入 `{refreshBalance:boolean,routeMode?}` 执行。POST `/api/checkin/batch` 输入 `{ids:string[],refreshBalance:boolean,routeMode?}` 最多 500 个明确账号，服务端并发 3、同站串行、同站同用户重复跳过，逐账号结果。
- 接口根地址规范化与余额适配器一致；外站只允许 `/api/user/checkin` GET/POST，以及用户明确选择签到后刷新余额时现有余额接口 GET。鉴权仅管理凭据。首次读状态、checked_in_today 决定是否提交；功能关闭、404、权限／登录／验证码、业务错误分别报告。不要向客户端返回原始 message/body/凭据。
- 扩展出站传输只能通过内部固定签到 POST 模式，空小 JSON 请求体，不提供任意 method/body 给客户端；保持 DNS/IP/代理/重定向拒绝/响应大小/压缩限制。签到 POST 没有自动重试或 401 重试。
- 月份／日期按真实日历严格校验；默认月份由站点默认响应记录决定，无法确定则明确为客户端请求月份，不推断站点时区；checked_in_today 与当前显示月份独立。记录最多 31 条，去重及完整性校验，数值非负且有界，原始配额与账号 quotaPerUnit 已确认换算分离，不跨站合计。
- 按库、账号和站点身份锁定；在 await body 后捕获凭据与连接版本。提交前重新校验配置／归档／存在；操作中更改配置不把旧结果写给新连接。别名分组变化不使缓存失效。
- 提交前持久化结果待确认屏障。任何可能已提交但响应不明的情况（超时、断连、无效响应、5xx 等）保持 uncertain，并禁止后续 POST，直到用户只读查到 checked_in_today=true；查到 false 仍不得自动重复提交，保留屏障并提示到站点确认。跨进程重启保留屏障，缓存未知初始状态。
- 独立缓存和操作记录表，严格验证、大小/数量限制、连接版本匹配、账号删除级联；旧库/备份继续可读，备份保持既有格式。操作记录留最近 100 条。奖励不能加到余额；可选真实余额查询失败不改变签到成功状态。
- 覆盖已签、关闭、成功、业务失败、未知、重复并发、同站去重、换配置、CSRF、缓存无网、凭据隐私、配额单位、无效日期、刷新余额失败、旧库兼容。每项任务完成后先规格审查，再质量审查，修复到通过。

## Task 2：详情月历与批量 UI

Create `src/components/checkin-panel.tsx`, `src/components/checkin-panel.css`, `src/components/checkin-batch-panel.tsx`; modify `src/components/workspace.tsx` minimally.

- New API 详情按钮「签到与月历」；打开只读缓存，点击「查询签到状态」才访问站点。缓存加载期间禁用操作，关闭／账号切换丢弃晚响应。月份切换读本地缓存，显示该月来源和读取时间，数据来自站点日期。
- 七列月历清晰显示签到日期／原始配额、月统计与累计统计区别、换算单位、近期操作结果。未知、未签、已签、关闭、需网页、失败、待确认准确显示。网页按钮采用账号公开 consoleUrl/siteUrl 安全链接。
- 「立即签到」先读状态再提交；可选「成功后刷新余额」，默认关闭，说明追加查询；余额响应用 workspace 更新账号的既有写边界，失败分别显示。
- 工具栏「批量签到」打开范围预览：有选择则选择范围，否则当前筛选；冻结 id 范围，显示具体账号和数量，用户点击「开始签到」才调用 batch。归档、不支持、已知已签/无凭据显示跳过原因，服务端再次核对。结果逐账号，无跨站奖励合计。
- 沿用现有 Modal/AtlasSelect/蓝珊瑚色与浅暗主题，手机可滚动、键盘聚焦、reduced-motion。忙碌时避免重复提交，开始后固定线路。没有轮询、定时任务或推理请求。
- 用下一任务浏览器 harness 先看到入口缺失 RED，再验收 GREEN；先规格审查后质量审查。
