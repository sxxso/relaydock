## 第一阶段设计（用户已批准的诊断方向）

- 账号详情新增「查询诊断」，在显式刷新/测试后显示最近一次结果；初始为空，不能编造阶段耗时。
- DNS、连接（HTTPS 包含 TLS）、等待响应头、读取 JSON、余额解析五个真实阶段。未执行显示未执行；字面 IP 的 DNS 显示无需解析。计时采用单调时钟，整个查询沿用 10/20/30 秒共享截止时间。
- 网络、权限、接口兼容、限流、站点拒绝/服务异常、安全限制、配置分别分类。HTTP 200 的业务拒绝不能直接断定密钥无效。
- 只保存最新一份白名单诊断，不保存请求/响应正文、头、凭据、DNS 地址、域名、路径、账号名或用户 ID。测试不新增余额快照，也不冒充成功同步。
- POST 测试/同步保持登录和 CSRF；sync 响应仍为 Account，增加可选 lastQueryDiagnostic；test 成功和查询失败响应带 diagnostic。浏览器只操作受保护内部 API。
- 复制报告重新通过白名单结构校验，只导出版本、平台、操作、时间、配置模式、耗时、固定错误码和 HTTP 状态。复制失败提供只读文本手动复制；不上传、不打开 Issue、不查询。
- 保留暖纸/墨绿视觉、清晰纵向阶段表和短反馈，无常驻动画；375/768/1440、浅深主题、减少动效均可用。
- DoH 仍为可选部署配置，不自动启用；不加入代理，不改真实凭据、配置或账号余额。第三方站点 的真实余额成功仍未确认。

### 实施顺序

1. `tests/diagnostics.test.ts`：先写时间/失败/报告脱敏断言，运行并确认红灯。
2. `src/lib/query-diagnostics.ts` + `src/lib/query-trace.ts`：共享白名单类型、固定文案、单调计时。
3. `tests/diagnostic-api.test.ts`：隔离 SQLite/本地 HTTP 夹具覆盖成功、测试、401/403/404/429、非法 JSON/余额、断流/超时、SSRF、持久化、未登录/CSRF。
4. `src/lib/outbound.ts`、`api.ts`、`store.ts`、`validation.ts`：记录阶段与结果，不增加请求、不泄露外部错误。
5. `src/components/query-diagnostic.tsx` / `.css` 和 `workspace.tsx`：接入最新诊断与复制。
6. `scripts/verify-diagnostics.ts`：隔离浏览器回归与截图；生产 UI 先验证红灯，完成后绿灯。
7. 新鲜运行单元测试、类型检查、构建、浏览器回归；评审修复后更新 STATUS 与此计划。

技术计时依据：[Node HTTP response/socket 事件](https://nodejs.org/api/http.html)、[Node 22 TLS secureConnect](https://nodejs.org/docs/latest-v22.x/api/tls.html#event-secureconnect)。响应等待只量到响应头，不能宣称测得站点内部处理时间。
