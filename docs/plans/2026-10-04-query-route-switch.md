# 查询线路切换

## 范围

- 刷新余额旁及设置页提供同一全局「直连 / 代理」分段按钮，沿用纸白、墨黑、松绿、细边与 160ms 控件反馈；无常驻动效。
- 查询代理地址/认证仍仅来自部署环境，界面和备份不包含它们。
- 首次使用保持旧行为：有部署代理则默认代理，否则直连。之后的明确选择保存在独立 SQLite meta，不随普通备份导入覆盖。
- 未配置/无效代理不可新选择；已选代理后来配置失效时拒绝请求，不擅自回退直连。
- 切换本身不查询、不做连接探测、不改环境、不重启。每个请求/批量开始时捕获线路，并在脱敏诊断记录；不修改 process.env 实现切换。

## 实施与验证

1. 先写线路状态/保存 API/传输隔离回归，验证 RED。
2. 受登录+CSRF保护的线路保存接口；单站/草稿可携带捕获的线路，未提供时使用服务器偏好。服务端逐请求显式决定代理。
3. 连接按钮、草稿/编辑/单站/批量查询和诊断；失败回滚、不让旧读取覆盖新选择；缺配置的指引不显示地址或凭据。
4. 新选择重载保持、空部署/非法代理、认证/CSRF、跨请求互不污染、批量固定线路、失败余额保留及脱敏回归。
5. 使用隔离 HTTP CONNECT 和站点夹具检查桌面/手机、浅深主题、按钮/键盘、保存失败、无自动查询；测试、typecheck和生产构建。

真实凭据/余额不用于本轮验证；不改用户 .env.local 或重启真实服务。历史只读诊断不替代新按钮验收。
