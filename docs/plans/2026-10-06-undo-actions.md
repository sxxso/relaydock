# 第三阶段：可撤销操作实施计划

> 日期：2026-10-06。目标是为收藏、归档、批量分组和批量标签提供短时撤销入口；不提交、不推送、不创建 GitHub 仓库。

## 目标

降低批量误操作成本，同时保证撤销不会覆盖用户在撤销窗口内产生的后续修改。

## 交付设计

- 前端只保留最近一次撤销动作，窗口约 6 秒；页面刷新不保留，不写入 localStorage。
- 快照只保存本次操作实际改变字段的旧值、账号 ID 和操作完成后的 `updatedAt`。
- 标签保存完整旧数组，不执行简单的反向 add/remove，以支持 replace 和顺序恢复。
- 服务端新增 `POST /api/accounts/undo`，严格只允许 `favorite`、`archived`、`group`、`tags` 四类字段。
- 服务端事务先检查所有 `expectedUpdatedAt`；任一目标发生后续修改时整批不写入并返回冲突项。
- 撤销不接受、不读取或恢复凭据、余额、历史快照、查询诊断、账号名称等字段。
- 撤销仍受登录、来源、CSRF、查询中账号保护和账号读写陈旧结果保护。

## 测试与验收

- 纯逻辑：字段白名单、标签数组复制、空快照、顺序比较。
- 存储层：收藏、归档、分组、标签恢复；冲突整批拒绝；余额、历史、凭据保持不变。
- API：认证、来源、CSRF、非法字段、整批冲突、方法边界及响应脱敏。
- 真实浏览器：收藏、批量分组、批量标签替换、批量归档的撤销入口；合成数据、零外站查询。
- 本地构建和类型检查通过后，才更新阶段状态；Docker、首次 GitHub CI 和真实平台查询仍不因本阶段验收而视为通过。
