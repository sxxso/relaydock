# 查询兼容与地图操作闭环

**目标：** 对照 CC Switch 分离传输错误和余额字段错误；新增/移动后聚焦目标；整组原子改名；验证同平台账号隔离。
**架构：** 保留受控 HTTP/HTTPS、DNS 固定与点击查询。传输层负责压缩/编码和脱敏响应分类，不放宽 SSRF 或自动跟随重定向。地图以显式操作序号请求聚焦，不因普通数据/布局变化重置镜头。分组事务同步账号及布局名。
**技术：** React/d3、Next.js、SQLite、Vitest、隔离 Playwright。

## 工作批次

1. 只读比较公开 CC Switch 请求实现及 RelayDock HTTP 字节处理。隔离响应夹具先 RED、后最小修复；HTML/防护、压缩损坏、空响应、字段不匹配独立诊断。绝不对实际站点进行未经新授权的查询。
2. `map-management.ts` 纯镜头决策/筛选恢复测试；保存回调返回实际账号；成功后选中/展开/必要时解除隐藏筛选；保留列表视图并滚动到对应行。失败不聚焦，普通余额/组移动不重置镜头。
3. `map/groups/rename` 事务含归档账号、位置、严格输入和版本冲突；重名拒绝。水墨分组操作增加改名入口，列表也可使用。先测后实现，密码/凭据/快照不得变动。
4. 同域同平台两账号夹具分别查询，验证 ID/凭据/历史不串号。不同账号同币种可汇总，令牌额度和账户余额仍需用户明确选择，不能把同一钱包重复记录误当不同钱包。
5. 新鲜全套测试、类型和隔离构建/浏览器验收。只在临时源副本构建，保留运行中的 3000 服务及真实 data/.env。产物只保留本轮必要报告和少量截图。

用户已批准：新增/移动必要时解除筛选；整组改名包含归档；目标重名不合并。无 Git 提交/推送。
