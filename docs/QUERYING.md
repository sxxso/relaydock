# 余额查询与网络排查

仅手动点击“测试连接”／“刷新余额”／批量刷新时请求。平台选择、表单保存、打开页面和等待不会查询。测试不记录快照；失败保留上次余额。每个查询默认总超时 10 秒，可明确选择 20／30 秒，无自动重试。

## 选对模板与凭据

- New API 账户：管理令牌，不是 sk- 模型 Key。按站点要求填写自己的用户 ID。根地址不要填聊天接口。
- New API 令牌：模型 Key，只显示该令牌限额；**不是账户余额**。无限额度不记成 0。已确认换算仅支持 USD/CNY，未确认保持原始配额。
- DeepSeek：API Key，选择响应实际提供的 CNY 或 USD；不自动换汇。
- OpenRouter：账户 credits 端点需要 **Management Key**；不把普通 Key 的个人限制冒充账户余额。
- SiliconFlow：官方于 2026-08-14 停用旧 /user/info，兼容模板仅用于仍提供旧接口的站点；官方账户先手动记录。见[官方公告](https://docs.siliconflow.cn/docs/release-notes/overview)。
- 自定义：GET 路径 + JSON 字段映射；不执行 CC Switch JavaScript 脚本。比完整脚本范围小，但可避免备份导入任意代码执行。路径如 /api/wallet，字段如 data.balance，结果可扣减并除以明确系数。

配置思路参考 [CC Switch 用量查询](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/zh/2-providers/2.5-usage-query.md)，端点按[New API 令牌文档](https://github.com/QuantumNous/new-api-docs/blob/main/docs/api/token-usage.md)、[DeepSeek](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)、[OpenRouter](https://openrouter.ai/docs/api/api-reference/credits/get-credits)核对。

## 超时不等于余额为空

| 提示                  | 核查                                                                          |
| --------------------- | ----------------------------------------------------------------------------- |
| DNS 失败／超时        | 系统解析是否异常；域名是否存在；服务器 DNS 是否可达                           |
| 建立连接超时／重置    | 部署服务器到站点的网络、端口、TLS、防火墙；浏览器／桌面程序可能正在走系统代理 |
| 等待响应超时          | 站点慢、阻断服务器客户端或服务不可用；可手动增加等待上限，但不能保证修复      |
| 读取响应超时／中断    | 站点返回了头但正文不完整                                                      |
| 401／403              | 模板与凭据权限，用户 ID，OpenRouter 管理 Key                                  |
| 404                   | 平台模板、根地址、站点是否开放该端点                                          |
| 非 JSON／缺少余额字段 | 网页挑战、登录页、模板不匹配；不会清零，也不会展示未脱敏原始响应              |

未配置代理且未明确选择线路时，服务端使用 Node 直连，**不会自动使用 Windows 系统代理或 HTTP_PROXY／HTTPS_PROXY／ALL_PROXY**。可按下节显式配置代理，再用界面切换查询线路；改变 DNS 并不等于走代理。不要取消证书校验，不要把临时解析 IP 硬编码进站点 URL。

## 空响应与查询出口

HTTP 200 不代表一定拿到了余额。正文为空或只有空白字符时，诊断码为 `response_empty`，尚未进入余额字段解析；不要按零余额保存，也不能据此判断管理令牌无效。非空但不合法的 JSON 仍使用 `invalid_json`。

若同一接口、令牌和用户 ID 在桌面客户端成功，而部署端返回空正文，应核对两端是否使用相同网络出口。先通过用户明确授权的只读测试比较直连与代理，不自动启用系统代理、重试、改变查询模板或关闭 TLS 校验。

## 可选 HTTP/HTTPS 查询代理（默认关闭）

部署者先配置 `RELAYDOCK_QUERY_PROXY_URL` 并重启服务，使代理线路可供选择。**「刷新余额」旁的「线路：直连 / 代理」和「设置 → 查询线路」是同一个全局开关**，切换后立即用于下一次点击查询，无需重启。开关不会启动代理软件、探测连接或刷新余额。

- 首次使用保留旧行为：已配置代理则默认代理，否则直连。明确选择后保存到本部署 SQLite，刷新页面和重启服务仍保留；不随普通 JSON 备份导出/导入，以免恢复资料时改变网络出口。
- 未配置/格式无效时，代理按钮不可用，设置页显示说明，不展示实际代理地址或认证信息。「格式有效」不等于网络已连通。
- 已选代理后若配置丢失/无效，查询拒绝并保留旧余额，**不会自动改走直连**；可手动切换直连。直连完全绕过代理，代理配置错误也不阻止直连。
- 单站、草稿测试和批量刷新捕获开始时的线路；同一浏览器查询期间锁定切换。批量每个请求仍使用起始线路，即使另一个窗口修改偏好或失败查询触发重新读取。
- 新脱敏诊断报告只增加 `routeMode: direct | proxy`，旧报告显示「线路未记录」，不推断历史查询线路。配置地址变更仍需重启；切换线路不会修改环境变量、自动启用 DoH 或使用系统代理。

不会从系统代理、浏览器设置、备份、查询脚本或其他代理环境变量推断代理地址。示例仅是占位值，不包含真实凭据：

```dotenv
RELAYDOCK_QUERY_PROXY_URL=http://proxy.internal.example:8080
# 或 HTTPS 代理，支持可选 Basic 认证；用户名/密码中的特殊字符需 URL 编码。
# RELAYDOCK_QUERY_PROXY_URL=https://proxy-user:URL_ENCODED_PASSWORD@proxy.internal.example:8443
```

- 只支持 `http://` 或 `https://` **HTTP CONNECT 代理**，不支持 SOCKS、PAC 或任意代理路径／查询参数。HTTP 和 HTTPS 目标都经 CONNECT；代理必须允许连接相应目标端口（不仅是 443，HTTP 常用 80）。HTTP 代理的 Basic 认证在到代理的链路上是明文，推荐 HTTPS 代理。
- **目标 DNS 不交给代理解析**：先在部署服务端通过现有系统 DNS 或显式 DoH 解析并验证全部答案，再发送 `CONNECT 已验证IP:端口`（IPv6 加方括号）。目标的 Host 保留原域名；HTTPS 在隧道内与目标做 TLS，SNI／证书身份仍为原目标。HTTPS 代理自身也正常验证证书，不提供关闭校验选项。
- 代理是独立的部署信任边界，可显式指向 localhost 或私有网络，不必加入目标允许列表。代理使用部署服务器的系统 DNS 解析，验证**全部**答案后固定代理 socket IP；元数据、链路本地、未指定、组播及其他禁止范围始终拒绝。私有代理不授予私有目标访问权限，目标允许列表与 SSRF 检查保持不变。
- 代理 Basic 凭据只发送在 CONNECT 的 `Proxy-Authorization`；站点令牌与 New-Api-User 只发送在隧道内的目标 GET，不发送给 CONNECT 或 DNS。**HTTP 目标的内容仍为明文**，代理能看到站点认证；HTTPS 目标有独立 TLS，但仍必须信任部署代理遵守固定 IP 转发策略，代理可观察目的 IP／端口与 TLS SNI。
- DNS、代理连接、CONNECT、目标 TLS、响应及读取共享原查询总时限；只发一次 CONNECT 和一次目标 GET，不重试、不跟随代理或目标重定向、失败不回退直连。目标正文仍限制 1 MB。配置不会自动启用 DoH；DoH 的解析服务连接独立于查询代理。

容器部署：现有基础文件为 `compose.yaml`；新增 `docker-compose.yml` 仅是可选代理环境覆盖。设置上述变量后，显式合并启动（不要单独运行覆盖文件）：

```sh
docker compose -f compose.yaml -f docker-compose.yml up -d
```

容器内的 localhost 指容器本身，宿主机代理需要使用容器可达的明确地址。临时不用代理可直接选择「直连」；移除代理配置前应先切换直连，否则保留的代理选择会拒绝查询，不会自动回退。

| 诊断码        | 固定安全提示与核查                                                           |
| ------------- | ---------------------------------------------------------------------------- |
| proxy_config  | 查询代理配置不正确；核对协议、端口、Basic 编码、禁止 IP，不把站点 URL 当代理 |
| proxy_auth    | 查询代理认证失败（407）；检查部署代理凭据，不要误改站点令牌                  |
| proxy_failed  | 查询代理连接／CONNECT 失败；检查代理 DNS、TLS、端口、CONNECT 支持与端口策略  |
| proxy_timeout | 查询代理 DNS／连接／CONNECT 超时；与目标共享总时限，不自动重试               |

上述提示、诊断标题及帮助文本均按固定代码生成，不包含代理地址、凭据或底层原始错误。隧道建立后的目标 TLS／等待响应／读取错误保留原有诊断阶段与代码。`tests/proxy.test.ts` 使用隔离本机假代理与合成证书覆盖固定 IP、认证分离、TLS-in-TLS、拒绝不安全地址／重定向、正文限制、总时限与安全公开提示；不代表真实代理或真实余额接口已经验证可达。

线路开关回归：`tests/query-routing.test.ts` 覆盖登录/CSRF、无查询切换、持久化/备份隔离、并发直连与代理、失效拒绝、脱敏及旧报告兼容；`npm run test:query-routing` 使用复制的生产构建和本机合成代理/站点，验证按钮、设置、失败回滚、批量固定线路、慢读取保护及响应式截图，不使用真实凭据或用户数据库。

## 可选 DNS-over-HTTPS（默认关闭）

在自己部署的 .env.local 或容器环境显式设置，再重启服务：

```dotenv
RELAYDOCK_DNS_MODE=cloudflare
```

恢复系统解析：设为 system 或删除该行。仅查询时把域名发送给固定 Cloudflare DNS 解析服务；站点凭据不发送给解析器。解析器本身及返回的所有目标 IP 仍校验，实际连接固定到已校验地址；不会接受任意备份指定的 DNS URL、跟随重定向或放行元数据地址。DNS 和 HTTP 共享总超时；DoH 不通不会自动回退系统 DNS。双栈答案优先使用 IPv4，不会发起第二次请求。

外部解析增加对第三方的域名可见性与网络依赖，故需部署者自己启用；没有修改任何现有 .env.local。DoH 解析协议与安全边界由自动测试覆盖，但当前网络环境尚未验证该分支到真实余额接口的完整成功路径。

## JSON 兼容与请求特征

- 查询响应现在支持 `gzip`、`deflate`、`br` 和 UTF-8 BOM。传输输入和解压输出分别限制为 1 MiB；压缩损坏、非法 UTF-8 或超限不会被保存成零余额。
- 在新增向导「地址与凭据 → 高级连接设置」，或「编辑站点」的查询配置中选择「请求特征」。默认「Atlas 默认」；可显式选择「CC Switch 模板请求头」，使用 `User-Agent: cc-switch/1.0` 与 `Accept: */*`。先保存再点击测试；切换本身不发起查询。
- 该选项仅改变允许的请求头，不复制桌面客户端的系统代理、Cookie、TLS 指纹、重定向行为或脚本执行；不能保证所有被防护的站点可查。查询线路仍需独立、明确选择，不会自动启用代理或 DoH。
- sub2api 或其他兼容站点必须按实际接口与凭据选择模板，不能仅凭平台名称把账户接口、登录 JWT 与模型 API Key 当成同一查询合同。

| 诊断码                   | 含义与下一步                                                           |
| ------------------------ | ---------------------------------------------------------------------- |
| `response_empty`         | HTTP 响应正文为空；核对接口和查询出口，不按零余额处理。                |
| `response_html`          | 收到 HTML 而非 JSON；核对最终接口、登录要求或访问规则。                |
| `response_challenge`     | 页面含疑似防护验证标记；只表示疑似，不认定具体防护厂商，也不自动绕过。 |
| `response_encoding`      | 压缩格式不支持、损坏或未完整结束。                                     |
| `response_text_encoding` | 解码后不是有效 UTF-8 文本。                                            |
| `invalid_json`           | 非空、非 HTML 正文仍无法解析为 JSON。                                  |

诊断报告仅包含白名单分类、请求特征、阶段耗时与字节数等元信息，不提供原始正文、令牌或代理认证信息。本轮这些路径使用本地夹具验证，真实供应商仍需由用户主动点击查询后复核。
