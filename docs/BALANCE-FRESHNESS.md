# 余额新鲜度 · 阶段 3

金额是最近一次真实记录，不是后台实时余额。地图、列表、详情使用同一套来源与时间语义。

## 看懂一条余额

例如：**上次余额 $28.50 · 接口查询 · 3 天前记录 · 最近查询超时**。

- **手动记录**：你在初始余额或「记录余额」填写的快照；即使站点平台是 New API，也不冒充接口查询。
- **接口查询**：显式刷新成功写入的快照。测试连接不会写快照。
- **来源未知**：兼容只有缓存金额、没有实际快照的旧数据。不按平台、诊断、导入日期猜来源。
- **尚无余额记录 / 未记录**：没有余额；不显示成零。明确记录 0 则正常显示零金额。
- 记录时间显示「刚刚 / N 分钟 / N 小时 / N 天前记录」，详情有完整年月日时分秒；日期可通过 `time[datetime]`、可访问名称与提示读取。使用浏览器本地时区。
- 如果备份中的记录时间晚于设备时间，会明确提示，不把未来记录说成「刚刚」。非法或缺失时间显示未知。

## 刷新与测试互不冒充

失败刷新保留原来的金额、单位、快照来源与记录时间，额外显示超时、网络失败、HTTP 权限类拒绝、接口兼容等固定分类。不根据上游异常文字推断。

连接测试的新结果单独标记 **未更新余额**，不会覆盖上次余额刷新失败；后续刷新成功才更新余额与真实快照并清除刷新失败。手动修正余额会换成手动来源，但不会隐藏最近余额刷新失败。

「查询平台」是当前配置的适配模板，不是这笔余额的来源。原始配额、令牌额度和自定义单位的隔离规则不变；不推算消费或做换汇。

## 持久化与性能

- 来源与记录时间只从 SQLite 实际余额快照关联读取；手动或查询成功时原子保存当前快照 ID，新记录不会被旧的未来时间或系统时钟回拨挡住。旧档案没有引用时按真实时间读取最新快照；只有缓存金额、没有快照时保留金额但来源与时间标未知。旧库启动事务中补充排序键/索引，不重写既有快照内容、金额或凭据。一次 SQL 使用索引，不为每个节点单独发 API，也不扫描所有快照来生成界面。
- 历史排序使用 UTC 毫秒键，不受 ISO 是否带小数影响；同毫秒用持久化序号确定顺序，列表按当前余额的实际记录时间排序。新导出 **v3** 携带稳定序号与当前余额引用，恢复后仍显示同一条实际记录。引用必须属于同一账号，错误引用预览与提交都拒绝。
- 仍接受 v1/v2：空库按原先最新在前的数组顺序恢复；合并时保留已有 ID 的序号。缺序号的新记录只在相对顺序可确定时补齐；遗漏本地同时间记录、已知序号顺序矛盾、排序键冲突或没有整数位置时原子拒绝，不猜测、不改已有记录来硬合并。序号是内部排序元数据（可为负整数），不是额度。只导入旧档案元信息且无新快照时保留当前有效余额引用。
- 最近余额刷新诊断与状态（成功时连同快照）原子写入，使用相同的查询完成时间精确关联；最新测试独立持久化，重启保留。旧记录无法确证对应尝试时只显示失败，不用 ±5 秒猜测。所有公开诊断与旧错误文本继续白名单脱敏。备份仍只保存档案、快照与设置，不包含诊断、会话或凭据。新部署恢复接口快照后，可确认来源，但没有查询尝试状态时显示「尚无查询结果」，不猜最近查询是否失败。
- 整个站点工作区只有一个对齐分钟的本地时钟；隐藏标签页时暂停，恢复时更新一次。离开站点页或退出登录销毁时钟；没有网络请求、常驻动画或逐节点定时器。
- 地图仍采用稳定 ID/分组布局，更新时间不移动节点或镜头；远景隐藏细节，聚焦后显示来源、年龄与失败简写，完整信息可通过节点的可访问名称或详情读取。

## 开发验收

```powershell

npm run build
npm run test:freshness
```

浏览器验收只使用临时 SQLite、无环境文件的独立运行目录、环境变量白名单、`127.0.0.1:3322` 和本地 HTTP 响应夹具；端口被占用即失败，不结束未知进程。截图/报告在 `output/playwright/freshness/`，图中账号与金额全部为夹具。详情截图会快速完成有限入场动画并断言最终不透明，地图先等待初始镜头就绪再比较时钟更新前后位置；这些是验收行为，不关闭产品动效。其他浏览器回归命令见 package.json。
